## Design decision

The 10-issue manifest does NOT fit a single autonomous wave. Issue bodies declare three hard dependency chains:

1. **`#27 PostgreSQL` and `#28 Alembic` both declare *"Depends on: SQLAlchemy ORM layer"*** (#26). #26 introduces SQLAlchemy models that #27 and #28 both consume.
2. **`#74 architecture.md` declares *"Depends on: All implementation slices complete"*.** It documents the post-Sprint-8 end-state.
3. **`#54 qe-check green` declares *"Depends on: All other slice-h-closure issues"*.** It is the closure verification step.

The footprint discovery (Phase 1.2) confirmed the dependency claims: **#26, #27, #28 all heavily modify the same 5 tool `db.py` files + `services/audit_log.py` + most DB tests** — 17 HEAVY-modify files in common. Parallelizing them produces guaranteed merge conflicts on every model + migration-number collisions in `backend/migrations/`.

#29 (S3/MinIO) and #30 (Redis sessions) are loosely coupled (share only `docker-compose.yml`, `requirements.txt`, and `app.py` — all LOW-risk additive changes) and can run parallel to a Wave 1 cut that excludes #26/#27/#28.

**Strategy**: Front-load Wave 1 with the loosely-coupled and standalone work (#29, #30, #122, #123, partial #74 draft). Defer the `#26 → #28 → #27` chain to Waves 2-4 as a single-stream serial chain. Wave 5 is closure (#124 operator exercise + finalize #74 + #54 verification).

## Conflict-cutting rules (Wave 1)

1. **Rebase daily**: each worktree runs `git fetch origin && git rebase origin/master` before pushing.
2. **Line budget**: each PR ≤ 600 lines (additions + deletions). Wave 1 streams are pre-scoped to fit comfortably; only Stream C is at risk (estimate ~450 lines including tests). If C exceeds 600, agent splits into (C-PR1) framework + storage helper + minio compose, (C-PR2) tool integration + tests.
3. **No migration numbering work in Wave 1** — `backend/migrations/` does not yet exist; #28 in Wave 3 creates it.
4. **Overlap check before promoting any new branch to parallel** (handled by sprint-kickoff Phase 0).
5. **`docker-compose.yml` rule**: only Stream C edits `docker-compose.yml` in Wave 1. Stream D does NOT need to (`redis:` service already exists, Stream D only wires `SESSION_REDIS_URL` in config). If D's agent attempts to edit compose, that is a kickoff-prompt failure.
6. **PR titles**: `QENG-16846: <type>(<scope>): <subject>`.
7. **Worktree cleanup**: `/sprint-close` removes worktrees post-merge.
