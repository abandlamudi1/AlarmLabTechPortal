## Friction encountered

### F21 — is_legacy_path incorrectly flags namespace-prefixed canonical keys as legacy (BUG)

- **Pattern**: `is_legacy_path()` used `"/" in value` to detect legacy paths. Canonical keys with a namespace prefix (`design_images/<file>`) contain `/` and were incorrectly classified as legacy, breaking migration idempotency on re-run.
- **Root cause**: The script's idempotency docstring said canonical keys have "no path separator", but the `migrate_column` call for `uploaded_image_path` uses `key_prefix="design_images/"` — producing canonical keys that DO contain `/`.
- **Recurrence**: new
- **Mitigation applied this wave**: Rewrote `is_legacy_path()` to check for known legacy filesystem prefixes (`data/`, `static/`, `uploads/`, `generated/`) and absolute paths instead of any `/` presence. Fixed the contradictory unit test assertion. (PR #146, commit a6d32cc)
- **Proposed action**: Add a rule to `docs/workflows/pr-review-tiered.md` or AGENTS.md: migration scripts that derive canonical keys with path-prefix separators must verify the `is_legacy_path` sentinel handles those keys correctly.

### F22 — MinIO container hostname in runbook docs used `localhost` instead of Docker service name

- **Pattern**: `S3_ENDPOINT_URL=http://localhost:9000` in the Docker runbook — works from the host machine but causes the app container to fail reaching MinIO since localhost resolves inside the web container, not to the MinIO container.
- **Root cause**: The env var example was written from the developer's host-machine perspective without considering container-to-container networking.
- **Recurrence**: new
- **Mitigation applied this wave**: Changed to `http://minio:9000` (the Docker Compose service name) in `docs/DOCKER_RUNBOOK.md`. (PR #144, commit d503481)
- **Proposed action**: Add to AGENTS.md or runbook review checklist: any env var example that references an S3/MinIO endpoint inside a Docker Compose stack must use the service name, not `localhost`.

### F23 — `logging.basicConfig()` at module scope in migration script

- **Pattern**: `logging.basicConfig(...)` placed at module import time in `scripts/migrate_legacy_paths.py`. Importing the script in tests (or in other tooling) silently overrides global logging configuration for the whole process.
- **Root cause**: The script was written as a standalone runnable without considering that the same file is imported by the test suite.
- **Recurrence**: new (related to F09 "module-level IO" general class, but distinct)
- **Mitigation applied this wave**: Moved `logging.basicConfig()` into `main()`. (PR #146, commit a6d32cc)
- **Proposed action**: Add to AGENTS.md hard rules: `logging.basicConfig()` must never appear at module scope in any file that is imported by tests. Move it into `main()` or `if __name__ == "__main__":`.

### F24 — `.dockerignore` excluded `scripts/` from Docker build context, breaking pytest import

- **Pattern**: `.dockerignore` contained a blanket `scripts/` exclusion. The migration script `scripts/migrate_legacy_paths.py` is imported by the test suite — `from scripts.migrate_legacy_paths import ...` — so the test stage had no `scripts` package at all, causing `ModuleNotFoundError: No module named 'scripts'` in CI.
- **Root cause**: `.dockerignore` was written when `scripts/` was purely dev/manual tooling. Issue #138 introduced a tested migration script there, but the `.dockerignore` comment ("not for runtime or pytest") was not revisited.
- **Recurrence**: new
- **Mitigation applied this wave**: Added `.dockerignore` negation rules to re-include only `__init__.py` and `migrate_legacy_paths.py` from `scripts/`, keeping all other dev scripts out. (PR #146, commit ebb8533)
- **Proposed action**: Add to the migration-script authoring checklist: if a new file in `scripts/` is imported by tests, its `__init__.py` and the script itself must be re-included in `.dockerignore` via negation rules.
