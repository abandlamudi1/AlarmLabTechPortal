## Friction encountered

### New: F13 — `adc_github_sdk` install path documented but still unblockable

- **Pattern:** User shared install instructions for `qe-repo-ai-assisted-guide` mid-wave (`pip install -e ".[dev]"` + `pip install git+…adc-jira-sdk.git`). Installation partially succeeded — `adc-jira-sdk` landed — but the editable install of `qe-repo-guide` failed because `setup.py` uses the deprecated `dependency_links` mechanism, so pip cannot auto-resolve the git+ entries in `requirements.txt`. `adc-github-sdk` (the module qe-check imports first) remains uninstalled.
- **Root cause:** `qe-repo-ai-assisted-guide/setup.py` parses `git+` URLs from `requirements.txt` and emits them as bare package names (`adc-github-sdk`) plus an entry in `dependency_links`. Modern pip ignores `dependency_links` (deprecated since pip 18), so it then tries to find `adc-github-sdk` on PyPI and fails.
- **Recurrence:** This is the third consecutive sprint where Stream C / #45 has been blocked by this dependency chain (Sprint 5, 6, 7). The first two were on `adc-jira-sdk` itself; this one is on the downstream `adc-github-sdk` plus the other ADC internal SDKs in the guide's requirements.
- **Mitigation applied this wave:** Stream C dropped; install recipe + failure mode persisted to user-memory (`reference_adc_github_sdk_and_qe_check.md`).
- **Proposed action:** Patch upstream `qe-repo-ai-assisted-guide/setup.py` so the git+ deps are resolved via modern PEP 508 form (e.g. `adc-github-sdk @ git+https://…`) instead of `dependency_links`. File against `adc-quality/qe-repo-ai-assisted-guide`. New issue.

### New: F15 — PyYAML 1.1 octal coercion silently corrupts all-digit option IDs

- **Pattern:** `priority_options.p2: 03271471` parses as octal integer `881465` under `yaml.safe_load`, not the string GitHub option ID. The Stream A Dev agent left the option IDs unquoted (matching style of the other letter-containing IDs around it).
- **Root cause:** YAML 1.1 (the version PyYAML defaults to) parses leading-zero all-digit scalars as octal integers. The risk is invisible at write-time and only surfaces when a downstream tool does `yaml.safe_load(...)['github']['priority_options']['p2']` and gets an integer.
- **Recurrence:** First observation. Recorded as F15.
- **Mitigation applied this wave:** All option IDs (priority/size/status) quoted defensively in PR #130; explanatory comment added above the `status_options:` block.
- **Proposed action:** Add a Hard Rule to AGENTS.md or a check in the skill-config preamble: "All `*_options` map values that could be all-digit must be quoted." Could also be enforced by a tiny pre-commit hook (`python -c "import yaml; assert all(isinstance(v, str) for v in yaml.safe_load(open('.claude/skills/skill-config.yml'))['github']['priority_options'].values())"`).
