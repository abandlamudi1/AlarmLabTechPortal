## Friction encountered

### Friction 1 — Module-level startup side effects without testing guard (new)

- **Pattern**: Stream A's dev agent placed `_check_redis()` as a bare module-level call in `app.py` and the original `celery_app.py` had `from app import app as _flask_app` + `celery = make_celery(_flask_app)` at module scope. Both execute on every `import app`, including during `pytest` test collection — causing 1 s blocking TCP probes and full Flask initialization on every test run.
- **Root cause**: Dev agent followed the minimal "make it work" pattern without considering that `app.py` is imported (not just executed) by the test suite.
- **Recurrence**: `new` — first observation in this project
- **Mitigation applied this wave**: Copilot caught both issues (comments 3 and 4 on PR #85). Fixed by gating `_check_redis()` with `if not (app.testing or os.environ.get("TESTING") == "1"):` and converting `celery_app.py` to a pure factory module.
- **Proposed action**: Add a line to `docs/workflows/dev-agent-checklist.md` (or AGENTS.md): "Any module-level side effect that touches I/O (DB open, network probe, subprocess) MUST be guarded against test-time execution."

### Friction 2 — Celery 5 silent uppercase config no-op (new)

- **Pattern**: `celery.conf.update(dict_with_UPPERCASE_keys)` silently ignores all keys in Celery 5 (which requires lowercase names). `result_backend` was never applied. The bug is invisible at import time — it only surfaces when a task tries to store a result.
- **Root cause**: Celery 4→5 breaking change: config keys must be lowercase. The dev agent was not aware of this and followed older patterns.
- **Recurrence**: `new` — first observation
- **Mitigation applied this wave**: Fixed by passing `backend=` directly to the `Celery()` constructor (not via conf.update) and filtering CELERY_* keys to lowercase before `conf.update()`. See PR #85 commit 29269d0.
- **Proposed action**: Add a note to the Celery integration pattern in `docs/patterns/` (new file) documenting the Celery 5 lowercase requirement. Proposed issue: see Recommended next actions.
