## Friction encountered

### New: F12 — Over-parameterization during centralization refactor

- **Pattern:** When centralizing constants into a shared config, the Dev agent collapsed *distinct* upstream values onto the same new `$CONFIG.*` key, breaking callers that depended on the distinction. Specifically:
  - `defer-pr-comments/SKILL.md` targets a **separate** project board (Project #26, ID `PVT_kwDODlOvwc4BPI7E`) with its own Priority and Size field IDs. The agent replaced these with `$CONFIG.github.project_id` and `$CONFIG.github.status_field_id` (which resolve to the main Project #23) — silently routing deferred-item writes to the wrong board and the wrong field.
  - Hardcoded `organization(login: "adc-quality")` was missed by the agent in `create-issue/SKILL.md` and `sprint-close/SKILL.md`. The agent's stated approach was "replace hardcoded literals with `$CONFIG.*`", but two files were skipped — both were callers whose comments above said `REPO_OWNER = adc-quality (derived from $CONFIG.repo)`, suggesting the agent matched on shell-variable form and missed inline GraphQL strings.
  - Markdown link **text** was parameterized to `$CONFIG.foo` while the link **target** remained literal — produces a rendered hyperlink showing the placeholder, not the path. Resolution mechanism (Option A: read-then-resolve) doesn't substitute at render time, so link text needs to stay literal.
- **Root cause:** The agent's "comprehensive grep self-check" treated all visually-similar literals as fungible. A literal like `PVT_kwDODlOvwc4BPI7E` looks like it belongs to the same project as `PVT_kwDODlOvwc4BOhf-` (same prefix), but they reference different projects. Same for field IDs.
- **Recurrence:** new (first observation)
- **Mitigation applied this wave:**
  - Extended `skill-config.yml` with `github.org`, `defer_project_number`, `defer_project_id`, `defer_priority_field_id`, `defer_size_field_id`
  - Reverted markdown link text to literal in `guide-friction-sync/SKILL.md:14` and `handoff/SKILL.md:280`
  - All four Copilot comments addressed in commit `bc91869`; parallel sprint-close fix in `9d5e4c0`
- **Proposed action:** Add a rule to `AGENTS.md` (or a Dev-agent prompt template addendum) for centralization-refactor work: *"When replacing a literal X with `$CONFIG.foo`, first verify that every callsite of X is referencing the *same logical value* — not a coincidentally-similar one. Group callsites by the entity they point to, then introduce one `$CONFIG.*` key per distinct entity."* Also: clarify that markdown link **text** should not be parameterized (only command/query parameters).
- **Watch for:** Future centralization-style refactors (e.g., consolidating env-var access, unifying logging configs). Same trap.
