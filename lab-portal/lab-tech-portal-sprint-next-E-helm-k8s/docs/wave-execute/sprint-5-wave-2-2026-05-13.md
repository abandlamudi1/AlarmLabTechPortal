## Friction encountered

### Friction 3 — Celery task autodiscovery not configured (new)

- **Pattern**: Stream E's dev agent added `tasks/periodic.py` but did not pass `include=["tasks.periodic"]` to the `Celery()` constructor in `celery_app.py`. Celery uses autodiscovery at startup — without `include`, the tasks module is never imported on the worker and all beat tasks fail at runtime with "Received unregistered task".
- **Root cause**: The dev agent followed the `@shared_task` pattern (which avoids circular imports) but did not realize that `shared_task` still requires the task module to be imported somewhere during worker startup. `include=` is the correct mechanism in this project's factory pattern.
- **Recurrence**: `new` — first observation
- **Mitigation applied this wave**: Copilot caught it (comment #2 on PR #96). Fixed by adding `include=["tasks.periodic"]` to the Celery constructor in `celery_app.py`.
- **Proposed action**: Add to `celery_app.py` header comment and AGENTS.md: "When adding a new tasks module, add it to the `include=` list in `make_celery()`." Also update the dev agent prompt template for Wave 3 (Stream J uses Celery tasks).

### Friction 4 — `crontab()` without explicit hour/minute fires every minute (new)

- **Pattern**: `crontab(day_of_week=0)` without `hour` and `minute` arguments defaults to `hour="*", minute="*"` — running 1440 times per day instead of once at midnight. The dev agent intended weekly execution.
- **Root cause**: Celery's `crontab` defaults are not obvious from the API name. The dev agent matched the schedule description ("Weekly") without checking default values.
- **Recurrence**: `new` — first observation
- **Mitigation applied this wave**: Copilot caught it (comment #1 on PR #96). Fixed by adding `hour=0, minute=0` to the weekly crontab call.
- **Proposed action**: Add a note to any future Celery Beat doc: "Always specify hour and minute explicitly — `crontab()` defaults to `*` for all fields."

### Friction 5 — `_ensure_task_columns()` called per-task-invocation (new, mitigated)

- **Pattern**: Stream G's `_update_task_status()` helper called `_ensure_task_columns()` on every task run, adding a `PRAGMA table_info` + possible `ALTER TABLE` on every Celery task execution.
- **Root cause**: The defensive approach from the agent prompt (handle the case where Stream H hasn't landed yet) was implemented as a runtime guard instead of a migration-time guard.
- **Recurrence**: `new` — first observation
- **Mitigation applied this wave**: Copilot classified as PERFORMANCE (comment on PR #97). Fixed by caching the check with a module-level `_COLUMNS_VERIFIED` flag so it only runs once per worker process.
- **Proposed action**: Add to AGENTS.md: "Schema migration checks belong in `_migrate_schema()` at DB init time, not in hot-path task code."
